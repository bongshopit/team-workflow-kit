One Jira story at a time, per repo, from the story only.

skills agents one Node script no third-party workflow tools
The design in three ideas

Who owns what

state

A script owns the state

  • team.mjs is the only writer of status.json
  • Legal transitions only, with exit codes
  • Every call is logged with time, states and reason
work

Agents do the work

  • Orchestrator routes, from next-action
  • QE designs tests, dev implements
  • Reviewer checks the diff against the proposal
decide

Humans own two gates

  • Gate 1 approve the approach and the test plan
  • Gate 2 review the PR and merge

The change contract lives in each repo and is committed with the PR.

Orchestrator explores the repo

Finds the code the story touches. init-change creates the change folder.

Proposal and test plan, in parallel

The orchestrator writes proposal.md and tasks.md while the QE subagent drafts test-plan.md. set-ready refuses a plan with a scenario that has no target.

Gate 1: a human decides

Reads the proposal and the test plan, then runs team approve PROJ-123 lead. Nobody else can move the change on.

Dev implements task by task

The orchestrator runs set-status applying first; the script checks approval, files and upstream repos. Then the dev: code, test, tick, commit.

Reviewer checks the diff

Every proposal point implemented, nothing out of scope, each AC covered by a test, tests pass. An open finding sends the change back.

Summary, audit and pull request

Summary by AC, merge order across repos, the audit of cost and flow, and a PR with the ticket linked.

Gate 2: a human merges

Reviews the PR, merges, then runs team set-status done.

Where we are

Proven, in progress, next

proven
  • Full flow with QE, dev and reviewer as subagents
  • Gate 1 and Gate 2 stay with humans
  • Multi-repo wait on the upstream repo
  • Call log, telemetry and hook join cleanly
  • Audit per ticket: cost, flow, skills, failures
in progress
  • Agents sometimes skip reading their skill
  • Orchestrator sometimes writes the test plan itself
  • Failed file reads: cause still unknown
  • Gates are protected by instructions, not yet by a hook
next
  • audit.json, quality counters, workflow version
  • /improve and the ledger
  • Sprint report and benchmark suite
  • Copilot CLI and IntelliJ, ACs from Jira, Java conventions
